Guía de módulos y pruebas — Psicomichi Web
1. Autenticación / Login
Descripción

Módulo encargado del acceso al sistema. Permite iniciar sesión, mantener sesión activa, refrescar token automáticamente y cerrar sesión de forma segura.

Qué probar
Iniciar sesión con credenciales válidas.
Intentar iniciar sesión con contraseña incorrecta.
Intentar iniciar sesión con usuario inexistente.
Confirmar que al iniciar sesión redirige al dashboard.
Confirmar que al cerrar sesión redirige al login.
Recargar la página estando autenticado y verificar que conserva la sesión.
Verificar que un usuario no autenticado no pueda entrar a rutas privadas como:
/dashboard
/users
/patients
/services
/appointments
2. Dashboard / Inicio
Descripción

Panel operativo inicial del sistema. Muestra un resumen diario con información de citas, pacientes y servicios activos. Sirve como centro de control para la psicóloga, asistentes o administración.

Qué probar
Confirmar que muestra el nombre del usuario autenticado.
Confirmar que muestra el rol y correo del usuario.
Confirmar que muestra métricas del día:
Citas de hoy.
Mis citas.
Citas pendientes.
Pacientes nuevos.
Crear una cita para el día actual y verificar que aparezca en el dashboard.
Crear una cita asignada al usuario actual y verificar que aparezca en “Mis citas”.
Verificar que las citas reagendadas sigan apareciendo como citas activas.
Verificar que las citas completadas, canceladas o no asistidas ya no aparezcan como citas activas.
Confirmar que el dashboard no truena si no hay citas registradas.
Confirmar que el dashboard no truena si hay citas sin responsable asignado.

8. Docker / Pruebas de despliegue frontend
Descripción

Setup para levantar el frontend en modo producción usando Docker y Nginx, facilitando que otras personas prueben el sistema sin instalar Node ni pnpm.

Qué probar
Clonar repo limpio.
Crear .env desde .env.docker.example.
Configurar VITE_API_BASE_URL.
Ejecutar:
docker compose up --build
Abrir:
http://localhost:5173
Confirmar que el login carga.
Confirmar que el frontend se conecta al backend correcto.
Confirmar que al recargar rutas como /dashboard, /patients, /services o /appointments no marca 404.
Confirmar acceso desde otra computadora en red local usando la IP del host.
Confirmar que si cambia VITE_API_BASE_URL, se reconstruye la imagen.
Checklist final del MVP

Antes de compartir para pruebas externas, validar:

pnpm lint
pnpm build
docker compose up --build
